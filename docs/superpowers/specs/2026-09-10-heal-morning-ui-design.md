# heal 清晨留白 UI 设计规格

**日期：** 2026-09-10  
**状态：** 已批准（brainstorming）  
**上游：** `docs/superpowers/specs/2026-09-10-heal-web-local-mvp-design.md`（业务流程不变）  
**范围：** 仅视觉与轻量交互钩子；不改存储 / 统计 / mailto / 四段业务逻辑

## 1. 目标

在现有纯静态 `web/` 上，把「默认灰白表单」提升为符合主题的 **清晨留白 × 雾蓝点缀** 界面：安静、可写信、封存有适中仪式感。

### 1.1 已确认选择

| 项 | 结论 |
|----|------|
| 气质 | 清晨留白（浅色、大留白、细线、轻仪式） |
| 封存动效 | 适中（约 1.2–1.8s 合封 / 纸面收拢） |
| 点缀色 | 淡墨灰 + 雾蓝 |
| 做法 | 设计令牌 + 轻量 HTML/JS 钩子（非仅改 CSS、非大重构） |

### 1.2 成功标准

1. 入口首屏：品牌 `heal` + 主句 + 一个主 CTA，不再像说明书堆砌  
2. 写信区具备信纸感；雾蓝仅作点缀  
3. 封存有可见合封动效；`prefers-reduced-motion: reduce` 时改为淡入成功态  
4. 归档清晰克制；业务流程与本地存储行为与改前一致  
5. 桌面与窄屏均可完成闭环  

## 2. 视觉系统

### 2.1 气质

安静清晨桌面：大留白、细线、淡墨字；雾蓝用于主按钮、焦点环、封存高光，不铺满渐变。

### 2.2 色板（CSS 变量）

| Token | 用途 | 值 |
|-------|------|-----|
| `--bg` | 页底 | `#F7F8FA` |
| `--surface` | 信纸区 | `#FFFEFB` |
| `--ink` | 主文 | `#2A2E33` |
| `--ink-muted` | 次要说明 | `#6B7280` |
| `--mist` | 点缀 / 主按钮 | `#5B7C99` |
| `--mist-soft` | 浅底 / 焦点 | `#E8EEF4` |
| `--line` | 细线 | `#D5DCE3` |
| `--danger` | 删除 | `#A65D5D` |

**禁止：** 紫渐变、大面积霓虹、默认深色模式、多层重阴影、大胶囊按钮堆。

### 2.3 字体

- **品牌 / 标题：** 中文衬线栈 — `"Songti SC", "Noto Serif SC", "STSong", "SimSun", serif`  
- **正文 / 控件：** `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`  
- 可选：国内可访问 CDN 增强开源衬线；失败回退本地栈  
- **不用** Inter / Roboto / Arial 作为品牌调性字体  

### 2.4 节奏与控件

- 内容柱宽约 `36–40rem`；段间距宽松  
- 主按钮：雾蓝实心；次按钮：淡墨线框；危险：低饱和描边  
- 圆角约 `4–8px`  
- 全局动效克制；仅封存有短仪式动画  

## 3. 四屏布局

### 3.1 入口（首屏一个构图）

- 品牌 `heal`：衬线、偏大，主视觉（非小导航字）  
- 一行主句：写给这次分开 / 无法送达的人  
- 短支撑：隐私本机 + 非治疗非挽回（细字，避免清单墙）  
- 主 CTA「开始写信」；文字链「本机已安放」  
- 援助链接与反馈在页脚，首屏不抢戏  
- 背景：`--bg` + 极淡雾蓝径向光晕（装饰，非插画主视觉）  

### 3.2 写信

- 居中信纸面：`--surface` + `--line` 细边框，内边距宽松  
- 场景选择：轻量控件外观（可 restyle 原生 `select`）  
- prompt：左侧雾蓝竖线 + `--mist-soft` 浅底  
- 正文区足够高；底栏：次要「保存草稿」+ 主「去封存」  

### 3.3 封存（适中仪式）

1. **确认态：** 摘要、勾选、可选断联标记（逻辑不变）  
2. **合封动效 ~1.2–1.8s：** 信纸垂直收拢或信封盖下合（CSS `transform` / `opacity`）；无音效、无粒子  
3. **已安放：** 大标题 + 短句 + 「查看归档」/「再写一封」  
4. **`prefers-reduced-motion: reduce`：** 跳过合封，淡入成功态  

钩子建议：`.is-sealing` / `.is-sealed`；JS 在 `confirmSeal` 成功路径加类，听 `animationend` 或短 timeout 后再展示成功态 UI。

### 3.4 归档

- 列表：细线分隔或轻底；标题 + 场景/日期；无重阴影卡片堆  
- 详情：只读信纸面；删除用 `--danger` 描边 + 现有 `confirm`  

## 4. 实现边界

### 4.1 做

- 主改 `web/css/app.css`（令牌 + 四屏样式 + 动画）  
- `web/index.html`：少量语义 class、封存动画壳节点、入口信息层次微调（文案语义不变）  
- `web/js/app.js`：封存动画类切换与 reduced-motion 分支  

### 4.2 不做

- 插画包、Lottie、音效  
- 暗色主题开关  
- 增删业务步骤、改 IndexedDB / 统计 / mailto  
- 引入构建工具或 UI 框架  

## 5. 验收清单

1. 入口符合「一个构图」：品牌 + 主句 + 一主 CTA  
2. 色板与字体符合 §2；无违禁风格  
3. 写信信纸感明确  
4. 封存合封可见；减少动态效果时安全降级  
5. 归档/删除可用；完整闭环与改前行为一致  
6. 窄屏可用
