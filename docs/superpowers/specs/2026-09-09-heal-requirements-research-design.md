# heal 需求调研设计规格

**日期：** 2026-09-09  
**状态：** 已批准（brainstorming）  
**仓库：** heal（空项目起步）

## 1. 背景与决策问题

### 1.1 背景

很多人经历「爱而不得」，不得不忍痛分开。这种关系割裂带来的痛苦难以安放。产品初衷是：为这类人群提供一个能够**发泄与安放**情绪的工具。

### 1.2 已确认约束

| 项 | 结论 |
|----|------|
| 产品形态 | 未定，由调研决定 |
| 人群情境 | 广义「失恋 / 失去亲密关系」（单恋无果、分手愈合、外部压力分开等均纳入大盘） |
| 市场 | 中国大陆优先 |
| 调研要拍板的事 | 要不要做 + 若做则 MVP 形态与切入点 |
| 资源 | 个人副业：业余时间、低成本、尽量单人可交付 |
| 商业化 | 先验证有人用；短期不追求赚钱 |

### 1.3 一句话目标

产出一份可决策的需求调研报告：回答「这事值不值得副业投入」以及「若值得，MVP 该落在哪种产品形态」。

### 1.4 范围

**做：**

1. **竞品调研分析** — 按产品形态建池，覆盖大陆相关品类；必要时用少量海外产品作参照，不作主战场。
2. **目标方向是否需要调整** — 对照初衷，判断过宽 / 过窄 / 可交付，并给出维持、微调或转向。
3. **未来前景分析** — 需求韧性、竞争烈度、副业窗口、主要风险（定性，不编造市场规模数字）。

**不做：**

- 不写产品代码、不画完整 UI、不写融资 BP
- 不做临床心理产品设计，不宣称「治疗」
- 短期不设完整变现方案（可附「以后若变现」难度备注）
- 不穷尽全网每一款 App；每形态取代表性样本即可

### 1.5 成功标准

报告读完后，决策者能明确三选一结果中的「做 / 暂缓」分支，并在「做」时锁定：

- MVP 主形态（五类之一，或明确的「主 + 辅」）
- 一句话定位
- 最小功能集

## 2. 调研方法：形态对照为主 + 旅程补强

### 2.1 主框架 — 五类产品形态

| 代号 | 形态 | 用户「发泄」方式 | 样本方向 |
|------|------|------------------|----------|
| A | 私密书写 / 情绪日记 | 写给自己，或写给对方但不发出 | 日记、情绪记录类 App |
| B | 匿名树洞 / 倾诉社区 | 被听见、被回应 | 树洞、倾听、话题广场 |
| C | AI 陪伴 / 疏导对话 | 随时倾诉、角色对话 | AI 心理 / 情感陪伴 |
| D | 仪式 / 关系归档工具 | 象征性告别、断联、封存 | 分手清单、信件仪式、归档小工具 |
| E | 内容 / 共鸣型 | 听他人故事、热评、播客式治愈 | 内容平台失恋话题、情绪电台等 |

每类抽取 **3–6 个** 大陆代表性样本；需要时每类最多加 **1 个** 海外参照。

### 2.2 统一评分维度（1–5 分）

对每款样本评分，并写一句依据：

1. **失去场景直击度** — 是否对准「分开 / 失去」，而非泛焦虑
2. **发泄即时性** — 打开能否立刻倒出来
3. **情绪安全性** — 隐私、二次伤害、沉溺诱导
4. **副业可复制度** — 单人业余能否做出「够用」版
5. **差异化空间** — 同质化程度；空白是否真实存在

另记录：核心功能、获客方式、明显短板、与 heal 初衷的重合度。

### 2.3 补强 — 用户旅程四阶段

不单独建竞品池，用于解释「谁在什么时候需要哪种形态」，并约束 MVP 不要做成全旅程平台。

| 阶段 | 典型需要 | 更可能匹配的形态 |
|------|----------|------------------|
| 冲击期 | 立刻倒出来 | B、C |
| 反刍期 | 反复想、想对对方说 | A、C、D |
| 抽离期 | 切断触发、做个了断 | D、A |
| 重建期 | 意义感、向前走 | A、E（或退出本产品） |

调研需给出：各阶段最缺什么；副业 MVP 应优先服务哪 **1–2** 个阶段。

### 2.4 质量底线

- 以桌面研究为主（应用商店、公开评测、内容平台讨论、产品介绍页）
- 每形态至少 3 个样本
- 评分可主观，但必须有「依据一句话」
- 区分事实与推断；不确定处标注置信度（高 / 中 / 低）
- 不编造下载量、营收等无法核实的数字

## 3. 方向校验与决策规则

### 3.1 校验对照

| 校验项 | 过宽信号 | 过窄信号 | 建议动作 |
|--------|----------|----------|----------|
| 人群 | 「所有情绪低落」都能用 | 只服务极小众情境 | 收敛到「失去亲密关系」或再收一层 |
| 场景 | 滑向泛心理健康 / 焦虑抑郁 | 只覆盖某一种分手 | 用旅程阶段选主战场 |
| 动作 | 社区 + AI + 仪式全做 | 只有瞬时功能、难形成完整体验 | 副业只保留 1 个主动作 |
| 承诺 | 暗示「治好你 / 挽回」 | 只发泄、无任何安放出口 | 定位为「发泄与安放」；明确非治疗、非挽回 |

### 3.2 「值不值得做」规则（副业约束）

满足以下 **至少 3 条** → 倾向 **做**：

1. 至少一类形态在「失去场景直击度」上普遍偏低（现有产品没对准）
2. 存在一个主动作，能在约 **2–4 周业余** 做出可演示 MVP
3. 用户能用一句话说清：为何打开你，而不是小红书 / 备忘录 / 通用 AI 聊天
4. 隐私与内容风险可控（例如不做重社区审核，或不碰高危 UGC）
5. 接受产品可能是「阶段性使用」，而非日活成瘾型

出现以下 **任一条** → 倾向 **不做 / 暂缓**：

- 五类形态都已被足够好的免费产品覆盖，且无独特切口
- MVP 必须依赖社区冷启动或高成本模型才有基本体验
- 方向滑向「心理咨询 / 医疗」表述，合规与专业成本超出副业

### 3.3 方向调整的合法结论（必须三选一写死）

1. **维持** — 仍是发泄工具，并明确主形态
2. **微调** — 例如从「广义发泄」改为更窄的主动作组合（如「写给无法送达的人 + 仪式封存」）
3. **转向 / 暂缓** — 赛道拥挤或副业做不动；可附替代观察项

## 4. 前景分析框架

在「副业、先验证使用」前提下，用四块**定性**判断，不做伪精确市场规模：

1. **需求韧性** — 失去/分手是否持续发生；替代行为（发动态、刷失恋内容、找 AI 聊）是否稳定存在
2. **竞争烈度** — 哪类已被「免费够用」占满；哪类仍是体验粗糙或场景错位
3. **副业窗口** — 单人能否做出可感知差异；是否必须烧钱获客；阶段性使用是否仍算成功
4. **风险清单** — 隐私、情绪依赖、自伤相关内容、UGC 治理、被归为医疗/心理咨询的合规压力；每条标注规避 / 接受 / 因此不做

前景结论用三档：**值得试 / 窄门可试 / 不建议现在做**，并写清关键假设（例如「若主做重社区则降为不建议」）。

## 5. 调研交付物结构

正式调研正文（执行阶段产出）建议章节：

1. 背景与决策问题
2. 用户旅程痛点补强（四阶段）
3. 五形态竞品对照与评分表
4. 方向校验结论（维持 / 微调 / 转向）
5. 前景与风险
6. 决策建议：做不做 + 若做则 MVP 一句话定位与最小功能集
7. 待验证假设（最多 5 条，供后续小范围访谈或原型验证）

本文件是「怎么调研」的设计规格；调研正文可在实施计划执行后另存（例如同目录下的 research 报告文件）。
